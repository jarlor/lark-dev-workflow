# 用本人已登录的飞书网页读取项目

用户选择本人网页接入，或明确不创建应用时，读取本文件。已有可用的 CLI 用户 profile 仍可继续使用；缺 profile 不授权新建应用、bot，也不允许借用其他项目的应用来凑齐配置。

## 适用范围

首版网页 helper 只读已有 Base 的结构、记录和评论，复用本人登录状态。项目绑定仍须为格式 2、`scope.mode=project_record`，并有真实表、字段和项目关联；`documents` 必须为空。非空 Docx 绑定暂不支持，保留原绑定并说明受影响能力，不能删掉文档配置来假装通过。

首次绑定旧表时，先核对原结构说明和实际字段，按 [接入步骤](onboarding.md#发现绑定与检查) 另存候选映射。网页读取不自动生成正式绑定，不套用最新版契约、不修改原表，也不替代维护责任的确认。`onboard.py` 和 `comments.py` 的远端采集命令走 CLI，不使用浏览器登录。

缺“反馈项目”字段时仍按 [旧表适配](project-mapping.md#没有反馈项目的旧反馈表) 选择可用范围。`linked_only` 不扫描未归属的新反馈；网页途径不能扩大这一范围。

## 浏览器与本人身份

- 使用目标 Linux 用户已经运行、已经本人登录的浏览器，以及它已有的本机连接地址（CDP）。地址只接受带端口的数字 loopback HTTP URL，例如 `http://127.0.0.1:9222` 或 `http://[::1]:9222`。不把浏览器端口开放到公网。
- 没有可用连接地址就说明缺口；不自动创建常驻服务、启动另一个浏览器、重启他人浏览器或更改其启动配置。先复用现有环境。
- 接入时从当前真实登录状态核实稳定的用户 ID，保存为 `browser-user-id`。显示姓名不能代替 ID；网页用户 ID 也不能未经核实当作 CLI 的 open ID。每次扫描核对实际账号，账号不符或已退出登录就停止本轮并说明，不切换身份绕过拒绝。
- 仅创建、操作并关闭本次自己的临时标签。保留原有标签、页面位置和筛选，不在正在使用的标签中导航或写入。
- 凭据留在浏览器。不得导出 Cookie、登录令牌或会话存储到配置、日志、对话、Git 或发布包。需要本人重新登录时说明具体动作；不在无人值守轮次等待终端输入。

## 配置与只读试跑

需要 Node.js 22+、Python 3.9+ 和 Codex CLI。沿用 [Linux 入口](unattended.md) 的项目规则、工作目录和运行权限。下面的路径、端口和用户 ID 都需替换为目标机器上已核实的真实值：

```sh
TASK_SKILL="$HOME/.agents/skills/lark-dev-workflow"
TASK_CONFIG="$HOME/.local/state/lark-dev-workflow/my-project-browser.json"

sh "$TASK_SKILL/scripts/unattended.sh" init \
  --config "$TASK_CONFIG" \
  --project-config /srv/my-project/.lark-dev-workflow/project.json \
  --workdir /srv/my-project \
  --access browser \
  --browser-cdp-url http://127.0.0.1:9222 \
  --browser-user-id verified-user-id \
  --interval-minutes 5

sh "$TASK_SKILL/scripts/unattended.sh" check --config "$TASK_CONFIG"
sh "$TASK_SKILL/scripts/unattended.sh" scan --config "$TASK_CONFIG"
```

安装位置以实际 Skill 路径为准。`init` 默认从 PATH 找 Node 并保存绝对路径，也可传 `--node-bin /实际路径/node`；不要把示例用户 ID 原样使用。网页模式生成格式 2 的运行配置，使用 `access`，没有 `lark_bin` 或 `lark_profile`。项目绑定和运行配置是两份不同文件，不相互覆盖。

`init` 只创建本地文件，不登录、不启动浏览器、不安装 cron。`check` 只校验本地配置，不证明浏览器可连、本人登录有效或评论已读完整。`scan` 才连接现有浏览器；它不启动 Codex、不改 Base，也不将业务事项记为已处理。

## 完整性与继续运行

每轮在新临时页面读取真实字段、记录和项目关联。评论通过当前网页的原生接口读取可见索引（含已解决线程）及网页已处理的全部回复，并核对索引、加载队列、回复编号和版本；网页尚未处理完返回数据时不能提交。读取范围是当前账号在该网页能取得的内容，不代表已验证服务端保留的全部历史。网页可能暂留刚删除的回复，因此不能仅凭一次缺席判断删除，执行或确认范围前仍要查回原线程。

整套表格和评论会再读一遍，两次相同才交给后续处理，避免用旧项目关联判断新评论。只看到首屏、记录数或评论数不算完整。缺页、来源不符、读取期间内容变化、格式改变或登录失效时，本轮失败并保留上次进度，不能用空数组表示“没有待办”。这项复核仍不等于数据库的原子快照；执行具体动作前要按项目规则再查相关记录与确认内容。

一轮网页扫描最多 5 分钟；超时后关闭自己的临时页并保留旧进度。定时入口已有单轮运行锁，上一轮未结束时不会叠加新一轮。表较多或网页较慢时，可以把检查间隔设为 10 分钟。

每台目标 Linux 都需按上述范围核实真实评论读取，不能把离线测试、记录读取成功或本地 `check` 成功写成这项验证已通过。未完成时保留暂停约定，先处理具体读取缺口；不直接执行 `tick` 或安装 cron。

网页 helper 只负责读取。流程字段须按实际返回的结构、当前节点和正常结束／终止状态单独验证，不能因为读到了类似单选的名称就声称流程能力齐全。节点推进须通过已验证的原生网页操作，不能绕过节点权限或必填项；AI 不完成人工确认节点。实际流程及迁移条件见 [完整流程](workflow.md#流程字段与旧副本)。

之后 Worker 需要写记录、回复或 @ 时，仍须按项目已有授权，通过已验证的本人网页操作，并另读一次最新记录或评论核对结果。提交结果未知先查回，不重复发送。只读扫描不证明写入可用，也不证明定时运行已经启用。真实读取完整且一次获授权工作试跑通过后，再按 [Linux 入口](unattended.md#配置并试跑) 启用。

## 保留旧进度

网页观察单独保存在运行状态目录的 `browser-comments-state.json`，与 CLI 的 `comments-state.json` 分开。账号或浏览器连接地址不符时拒绝覆盖旧观察；不修改旧回执来消除这个提示。

切换访问方式时，先暂停旧运行器并等当前轮次结束。另存候选配置，保留旧配置、观察记录、checkpoint 和中断证据；不自动迁移或清空。只读核实新方式后，仍按正式 Base 中的来源键、业务关联和真实回执查重，不能把换后端当作重新执行已完成事项的理由。恢复已停业务仍需沿用原授权和停止约定。
