# 给同事看的文字

先想这句话会出现在哪里，谁要看。用同事平时说的业务名和页面上的按钮名。让他只看第一句就知道需要做什么，或者哪个地方发生了什么变化。

## 请人做一件事

- **请他补资料。** 直接问缺的那样东西。例如“请发一张上传失败时的截图。把页面上的提示和文件大小一起截进去，发到这条反馈下面就行。”
- **请他确认。** 告诉他在决定什么，按页面上实际出现的按钮写操作。例如“请看看这版计划。我们准备在文件太大时显示原因和大小限制。同意就到「待确认计划」点「完成节点」。想改的地方直接留言。”旧副本使用普通状态选项时，写实际要选的状态。
- **请他在几种做法中选一个。** 说出他会看到什么差别。例如“导出时，你希望只导出当前页，还是把筛选出来的所有页一起导出？”已经答过的部分直接沿用。
- **请他试一下。** 写真实可试的操作和要观察的结果。例如“请传一张超过大小限制的图片，看看页面有没有告诉你最多能传多大。把看到的提示写在测试记录下。”

个人待办按件分段。第一行写当前的问题或动作，下一行只补会影响操作的条件，末尾放直接打开这条记录的链接和编号。一个旧标题很长、和当前问题对不上时，照当前有依据的请求提问。不要拿旧标题替人补出一个新的意思。

## 让人读懂记录和结果

| 写在哪里 | 怎么写 | 例子 |
|---|---|---|
| 标题、问题说明 | 写出页面、动作和看见的现象 | 上传图片后看不到预览 |
| 研发计划、验收标准 | 写清会改什么、怎么知道改好了 | 图片太大时显示大小限制。用一张超限图片和一张正常图片分别试一次。 |
| 进度、交接、发布通知 | 写已经做到哪一步、还缺哪一步 | 测试版已经能显示大小限制。手机端还没试。 |
| 阻塞、下一步 | 写出眼下能做的动作，确实缺人帮忙时点明需要什么 | 我打开测试页时看到“没有访问权限”。请把这个测试账号加到试用名单里。 |

保留影响使用或决定的条件，例如哪些页面会改、什么时候生效、是否要停机、是否会收费。原话和已确认的范围可引用，另外写一句好懂的说明；编号、版本、错误码按真实值保留。旧记录按原样留存。需要身份说明时交代真实来源。

发出前删掉只对处理人有用的术语和过程。“补齐异常证据”可以写成“请把报错时屏幕上的提示发过来”。只是内部登记、查重、更新进度时，完成记录即可。需要同事回答、操作，或者结果会影响他时，再按项目约定发消息。
