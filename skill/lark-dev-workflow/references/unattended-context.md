# 减少重复输入

只在本轮提示需要交接，或已经执行写入并取得读回证据时读取。以下文件仅保存在运行器给出的本轮私有目录，不写入公开仓库或飞书，不修改运行器的 state、checkpoint 或配置。

## 交接后再使用新会话

运行器默认每个会话成功完成 4 轮后考虑换一个新的 CLI 执行会话；可在 Linux 运行配置中用正整数 `session_max_runs` 调整。失败不计入成功轮数。旧会话编号、运行文件和恢复证据保留；没有有效交接、仍有在途操作或正在恢复失败时继续原会话，不强行清空历史。

`session_policy.handoff_due=true` 时，在结束本轮前将可核实的交接保存到 `session_policy.handoff_file`。内容至少保留：等待答复、外部结果、未验收及未交付的事项；已确认的具体范围和版本及其原回复位置；执行授权、事项停止决定与恢复条件。已有正式记录和本轮项目规则可作为来源，不复制长历史。摘要不能替代原始依据，新会话在安排开发或执行敏感动作前仍须核对适用原文。

格式如下，示例来源须替换为本项目真实位置；`run_id`、`snapshot_id` 原样使用本轮值：

```json
{
  "format_version": 1,
  "run_id": "本轮编号",
  "snapshot_id": "本轮快照编号",
  "can_start_fresh": true,
  "summary": "本轮已完成哪些工作，当前主要在等什么",
  "open_items": [
    {"source": "真实记录键或证据位置", "next_step": "还需处理的具体动作"}
  ],
  "constraints": [
    {"source": "原确认、授权或停止决定的真实位置", "rule": "具体适用范围、版本或限制"}
  ],
  "active_operations": []
}
```

无法把必要上下文交接清楚时，将 `can_start_fresh` 设为 `false`。仍在运行的外部任务、未确认结果的写入或其他依赖当前执行现场的操作，必须列入 `active_operations`，每项用文字或对象写清操作编号、实际目标、证据位置和下一步；该列表非空就不会换会话，不得为了换会话而写空。`open_items` 只有确实无待办时才能为空。普通等待人回复可交接，但必须保留原问题和未获确认的内容。

交接文件仅在本轮成功完成后可供下一轮使用。它不表示项目完成，不改变等待时间、业务关联或已有确认，也不要求用户重新确认原本已确认的内容。新会话失败后恢复该次会话及其在途证据，不回到旧会话重复执行。

## 已核实的自身写入

本轮实际更新了已有记录字段，或新增／编辑了自己的评论，且已经从飞书读回准确结果时，可在 `optional_effects_file` 保存精确变更。不要为生成这个文件再扫描整表；利用本来就需要的写前核对和写后读回。没有合适证据就不生成，下一轮照常检查。

```json
{
  "format_version": 1,
  "run_id": "本轮编号",
  "snapshot_id": "本轮快照编号",
  "record_fields": [
    {
      "record_key": "真实表ID/真实记录ID",
      "field_id": "实际更新的字段ID",
      "before": "本轮开始快照中的原值",
      "after": "本轮写入并读回的值",
      "readback_evidence": "实际私有读回文件或工具结果位置"
    }
  ],
  "comments": []
}
```

只列本人在本轮实际写入的字段；禁止把开始与结束快照的全部差异反推为自己的操作，这可能包含同时到来的人工修改。与开始快照不一致的写前值不能强行套用。保留原始 JSON 类型，不将人员、关联、选项等值改成显示文字。每个字段只列一次；本轮多次更新同字段时，使用开始快照原值及最终已读回值。新建记录、删除、线程解决或范围改变暂不适用，按原流程检查。

评论项使用 `event_key`、`before`、`after`、`readback_evidence` 四个字段；前后值须为 `watch.py` 的完整规范评论对象（含内容、修订、位置与线程信息），新增评论的 `before` 为 `null`。只能从实际读回构造，不手写或猜测哈希；格式以 `scripts/own_effects.py` 为准。缺完整规范对象时可不记录该评论，不为省一轮而伪造。账号相同不等于 AI 发言，绝不能把人的新回复列入自身写入。

运行器验证格式与原值，但不能仅凭文件认证一次写入确由谁操作。下一次完整扫描必须与“开始快照加上这些精确变更”完全一致，才省掉一次无用唤醒；任何额外回复、不同字段值或其他变化都会继续交给 AI。到期的续办和定期检查也继续执行。无文件、文件无效或证据不足时，安全回到原流程，不丢弃变化、不暂停项目。
